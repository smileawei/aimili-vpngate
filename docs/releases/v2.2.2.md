# AimiliVPN V2.2.2

本版本修正节点网络延迟的测量与展示，保留 V2.2.1 的 Web 上游代理设置和默认直连行为。

## 更新内容

- 节点列表、活动节点与节点排序统一使用本机直连节点的 TCP 建连耗时，不使用 Ping，也不经过配置的上游代理。
- 不再将 SoftEther 握手、DHCP、出口验证或代理请求耗时当作节点网络延迟。
- TCP 测量自动选择物理出口网卡，使用单调时钟计时，避免系统时间调整影响结果。
- 测量失败时不写入虚假的实测值；有官方预估时显示带 `~` 的提示。
- 代理出口及热备的 HTTPS 耗时单独标为“请求耗时”，便于区分节点网络延迟与出口访问速度。

## 升级

保留已有 `data/` 目录，使用本版本的 Compose 配置执行：

```bash
SOFTETHER_IMAGE_TAG=2.2.2 docker compose -f compose.ghcr.yaml pull
SOFTETHER_IMAGE_TAG=2.2.2 docker compose -f compose.ghcr.yaml up -d
```

如需固定版本，在 `.env` 设置 `SOFTETHER_IMAGE_TAG=2.2.2`。
Web 上游代理配置继续保留；从旧版预置上游地址的 Compose 升级时，请参阅 [V2.2.1 升级说明](v2.2.1.md)。
