# AimiliVPN V2.2.0

本次为 smileawei fork 的首个功能正式版，包含 SoftEther 主备连接、故障恢复、后台展示与切换历史统计。

## 主要更新

- SoftEther SSL-VPN 后端：主连接和热备独立维护网卡、DHCP、路由，通过可配置的上游代理连接 VPNGate。
- 一主一热备：故障时提升已经验证的热备，并后台补齐备用；可用候选在满足住宅、地区、收藏限制后优先同地区。
- 切换防抖：快速检测失败后增加 3 秒双地址复核，排查共享上游故障，降低短时抖动引起的误切。
- Web 后台：独立主备状态卡片、角色高亮、默认按代理设置筛选可用节点、手机布局、浏览器本地时间日夜主题。
- 切换历史：按日期及结果筛选，记录前后节点、原因和结果，独立保存约 90 天，兼容旧日志导入。
- IP 变化统计：支持 h/day/week，只默认统计成功且实测出口改变的操作；历史节点 IP 推断需单独勾选，不混入已确认数据。
- 可选内网免登录：保留默认认证策略，也支持关闭登录及空安全路径。
- 应用更新入口及安装器默认指向本 fork，避免更新回上游而丢失本仓库功能。

## Docker 镜像

推荐使用带主备功能的 SoftEther 镜像：

```text
ghcr.io/smileawei/aimili-vpngate-softether:2.2.0
```

支持 **linux/amd64、linux/arm64**，同时发布 `2.2`、`latest` 标签。
原 OpenVPN 镜像为 `ghcr.io/smileawei/aimili-vpngate:2.2.0`，保留 amd64、386、arm64、arm/v7。

在本仓库目录运行：

```bash
SOFTETHER_IMAGE_TAG=2.2.0 docker compose -f compose.ghcr.yaml pull
SOFTETHER_IMAGE_TAG=2.2.0 docker compose -f compose.ghcr.yaml up -d
```

需要长期固定版本时，在现有 `.env` 中设置 `SOFTETHER_IMAGE_TAG=2.2.0`。
保留原 `data/` 目录，凭据、代理配置和切换记录会继续使用。SoftEther 默认 Web 端口为 8787，代理端口为 7929；上游代理默认 `socks5://10.220.10.253:1081`，可用 `SOFTETHER_UPSTREAM_PROXY` 覆盖。

## 源码与验证

发行附件包含完整源码包和 SHA-256 校验文件，包含原 OpenVPN 与 SoftEther 的源码和 Compose 配置。
107 项回归测试；发布流程覆盖 Python 3.9 / 3.11 / 3.13、各镜像架构的模块导入、SoftEther 客户端启动，以及源码包解压后的独立校验。

热备就绪时才可直接提升；现有 TCP 连接仍需客户端重连。共享上游本身故障不属于主备能独立覆盖的范围。
旧日志未保存实测出口 IP，因此旧数据默认不进入已确认 IP 变化统计。
